💾 Storage Architecture

All data assets are stored in S3-compatible object storage, not on Render's ephemeral disk:

  • Provider: idrive e2 (S3-compatible)
  • Endpoint: g7h4.fra3.idrivee2-51.com
  • Bucket: databricks
  • Why S3: Render's filesystem is ephemeral — files are lost on redeploy/restart. S3 ensures permanent, durable storage.
  • Access: Server-side only — clients never touch object storage directly (ADR-0006)

How It Works — End-to-End Walkthrough

1. Registration & Verification

A new user registers as either a data_consumer or farmer_organization. They must accept the current Terms of Service version at sign-up.

POST /api/v1/register
{
  "email": "user@example.com",
  "password": "••••••••",
  "display_name": "Jane Farmer",
  "role": "farmer_organization",
  "tos_version": "1.0"
}

In dev mode, the verification link goes to the server log. In production, it's emailed.

2. Farmer Organization Uploads Data

A Farmer Organization uploads datasets (CSV, documents) as Data Assets. At ingest:

  • Anonymization — personal data (names, emails, phones, coordinates) is stripped or pseudonymized
  • Taxonomy classification — the Jev classifier (via MindsHub) categorizes on six axes: crop, region, growth stage, intervention, outcome, data type
  • Pricing — cached price from the current price book

Assets are stored server-side in S3. Clients never touch object storage directly.

3. Data Consumer Browses Catalog

Data Consumers browse the Catalog — a read view across all Farmer Organizations' shared assets with taxonomy facets, filtering, and pricing. They can also correct taxonomy assignments (the org's correction becomes truth).

4. Request Creation & Clarification

A Data Consumer creates a Request — commissioning existing Assets and/or a new Collection with format, quality bar, and credit budget.

Request Created
→
Agent Clarifies
via web Channel
→
Budget Approved
→
Collection Starts

The AI agent chats with the consumer to clarify requirements, using the Model Gateway (GLM) for inference. Every inference is metered in micro-credits.

5. Data Collection from Farmers

The agent reaches out to Farmer Members (individual farmers, no platform account) over Channels (WhatsApp, Telegram, email, web, voice) to gather the requested data.

Collection outputs are anonymized before delivery — shared data cannot identify individual farmers.

6. Payment & Revenue Share

Credits are the internal currency. The Ledger records every movement with double-entry bookkeeping:

  • Consumer pays credits for the Request
  • Farmer Organization receives Revenue Share
  • Platform retains its portion
  • Agent inference costs are metered

Memory MCP — Status

Design: Pluggable MCP Memory Providers

Thresh implements no memory architecture of its own. Following the Hermes Agent pattern (ADR-0003), the agent runtime connects to external memory services over MCP:

  • mem0, Hindsight, supermemory, Honcho, ...
  • Configured by Platform Admin, swappable per deployment
  • Multiple providers can be connected simultaneously

The PhD thesis's Iterative Routing algorithm can later be exposed as an MCP memory server and connected like any other provider — no product changes needed.

Hindsight Integration — Current Status

✓ Fully Operational (2026-10-12)

  • ✓ Hindsight Cloud MCP endpoint: https://api.hindsight.vectorize.io/mcp
  • ✓ Bearer auth via HINDSIGHT_API_KEY environment variable
  • ✓ Tool name mapping: Thresh's recall_memory/store_memory → Hindsight's recall/retain
  • ✓ Registered as memory provider hindsight-prod via admin API
  • ✓ Agent redeployed with integration code (commit 78416c5)
  • ✓ Live tested: retain stored "Green Valley Farms specializes in winter wheat" → recall retrieved it with 1.09 relevance score
  • ✓ Graceful degradation: failures return empty, never break the conversation

How it works: The agent's http_connect detects Hindsight endpoints and injects the API key as a Bearer header. On each clarify turn, the backend passes configured provider endpoints; the agent recalls relevant memories before responding and stores new facts after.

Memory Provider Configuration

Platform Admins configure memory providers via the API:

POST /api/v1/admin/memory-providers
{
  "name": "hindsight-prod",
  "mcp_url": "https://hindsight.example.com/mcp",
  "enabled": true
}

The agent discovers and connects to all enabled providers at startup.

Key Technical Details

  • Jev classifier: MindsHub API with curl-like User-Agent (bypasses Cloudflare 403)
  • CORS: THRESH_ALLOWED_ORIGINS env var controls allowed frontend origins
  • Agent port: AGENT_HOST/AGENT_PORT (not THRESH_AGENT_ADDR)
  • Python deps: mcp must be in main dependencies, not just dev
  • Free tier caveat: Render services spin down after inactivity (~50s cold start)
